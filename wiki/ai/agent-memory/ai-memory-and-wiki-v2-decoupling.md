# AI 独立第二大脑（one-memory）与人类知识库（Wiki V2）物理隔离架构

## 1. 架构本质与第一性原理

* **核心矛盾**：传统 Agent 将机器配置碎片写入知识库，导致人类阅读体验恶化；将全部参数塞入 Prompt 记忆，导致上下文爆炸与幻觉。
* **物理隔离方案**：
  * **AI 记忆库 (`one-memory`)**：AI 的第二大脑，管理本能常识（如 Token 变量直取）、部署状态、时序事件流与外部 Wiki 寻址指针。
  * **人类知识库 (`one-wiki-v2`)**：人类专属的冷热物理隔离高密度深度知识库，保持纯净，供人类阅读与 AI 按需借阅。

---

## 2. 人类记忆的“两念流转模型”

```text
情境触发 ➔ 【第一念：one-memory 记忆闪回】
          - 感知“我掌握本能” 或 “我知道该思考在 Wiki 某处”
          - 极简条目，不存物理数值（低 Token）
                │
                ▼
          【第二念：物理底稿精准翻阅】
          - 若为机器本能：直接去固定环境位置 (如 exports) 提取最新参数
          - 若为人类深度知识：按外部指针精准调阅 one-wiki-v2/wiki/ 文档
```

---

## 3. 记忆系统的三维回忆机制

| 回忆维度 | 触发场景 | 记忆寻径 | 最终执行 |
| :--- | :--- | :--- | :--- |
| **📅 时序回溯** | “我们昨天干了什么” | 查 `memories/timeline/YYYY-MM.md` | 输出当日事件脉络与概要 |
| **🔍 场景感知** | “之前做过监控大屏吗” | 匹配领域卡片概要 (`worldmonitor.md`) | 感知已做过，调阅内部底稿 |
| **⚡ 动作指引** | “如何配置 AI Token” | 匹配动作指针 (Action Pointer) | 直达专用 Skill (`one-config-...`) |

## 4. 艾宾浩斯复习问答（SRS Q&A）

### Q: 为什么 AI 记忆库与人类 Wiki V2 必须物理彻底解耦？
**A:** 人类 Wiki 是供人类深度阅读的高密度资产，必须保持纯净；AI 记忆库自给自足处理机器琐碎并维护本能，仅在需要时通过外部指针单向引用人类 Wiki，实现“拟人化第二个我”。

## 5. 未来演进设想：高频肌肉记忆区（LRU 动态热池）

* **痛点**：日常高频操作（如 Git 提交、常用别名）是纯粹的本能肌肉记忆，无需翻文档，也不该去多级记忆库做复杂检索。
* **设想机制（待实现）**：
  1. **独立 L1 热区 (Working Memory)**：为高频提示词与日常命令开辟专属轻量存储区。
  2. **自适应 LRU 淘汰机制**：经常用到的内容自动上浮保活，长期不用的内容自动淡出移除，保持热区极简。

---

## 6. 终极设计哲学：拒绝“20 年前 PPT 炫技”，打造真实“记忆外挂”

* **批判假装智能（PPT 式自嗨）**：盲目让 AI “自动联想记忆”（“根据你最近弄的路由器…”）是 20 年前 PPT 图标乱转的炫技产物，除了污染上下文注意力毫无价值。
* **人类主权与外挂范式**：机器没有生命，记忆只能外挂。默认保持无记忆干扰的极纯思考状态；当且仅当人类主动指令召回时，才精准挂载对应记忆与指针。
