# AI 编程上下文工程与注意力控制模型

## 一、AI 编码的核心瓶颈：上下文衰减与污染
大模型有效推理能力随上下文长度增加而发生“注意力稀释 (Attention Fade)”。把所有代码或文档盲目填入 Prompt 会直接导致：
1. **幻觉剧增**：模型在无关文件中抓取错误签名；
2. **推理降级**：无法抓住用户真正的核心痛点；
3. **成本高昂**：重复搬运低密度代码。

## 二、三层上下文架构（Karpathy 哲学）

```text
┌────────────────────────┐
│  第 1 层：系统原则与宪法  │ -> AGENTS.md / 极简规则（常驻，极低 Token）
├────────────────────────┤
│  第 2 层：项目统一上下文  │ -> CONTEXT.md（项目是啥/主要部分在哪/设计原因）
├────────────────────────┤
│  第 3 层：按需动态装载  │ -> 具体源码文件（按图索骥，用完即扔）
└────────────────────────┘
```

## 三、实操铁律
* **Think Before Coding**：动笔前先暴露权衡，明确假设；
* **极简沟通**：只答结果与结论，能用一句话绝不用长篇大论；
* **单次暗号授权**：修改代码必须有明确的单次暗号（如 `aaa`），防止 AI 盲目自作主张。
