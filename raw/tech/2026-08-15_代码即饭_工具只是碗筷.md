# 只做入口，只做记笔记 / 代码即饭，工具只是碗筷

## 一、核心心法：只做记笔记，代码即饭，工具只是碗筷

关于选择某些工具，其实都不重要。我们现在只做一个入口，只做输入（或者说只做记笔记），把我们生成的内容先存起来，这是我们现在的重中之重。

把这些内容存起来之后，在我们浏览的时候，我们可以用各种方式去处理。就像用 Understand Anything 去理解"屎山代码"一样，如果我们写了很多知识，也是一堆很乱的东西，像"屎山代码"一样，那我们后续可以用 Understand Anything，或者用 Graphify，或者用我们自己的技能，甚至直接跟 AI 聊，这都无所谓。

所以，我们只要把第一步做好，也就是把知识先存起来，这就够了。后面的那些东西我们暂时不研究了，目前最多研究一下 Graphify，然后再用一下我们自己的就可以了。

---

关于代码的知识图谱，道理是一样的。我们的代码就相当于我刚才说的那个文档。

我们先把代码产生出来，管它是屎山代码还是什么代码，只要代码已经产生了，我们未来可以用 Understand Anything、Graphify，或者我们自己的技能去生成蓝图、生成 Map 都可以；或者我们手动给它喂数据让它写文档，这都行。最终我们手动写好文档，然后把手动教 AI 做的那些事情总结成 Skill，这也可以。

最主要的一点是：**代码才是我们的知识源**。只要代码在，后面依照这些生成的那些东西都不重要，所以我们不用再纠结用哪个工具了。

从明天开始，我们的代码库这个用 Understand Anything，那个用 Graphify，下一个用我们自己的，或者混合着乱用都无所谓，反正非常灵活。

这就跟今天吃饭一样，用这个碗、用那个筷子，三双不一样的筷子、三个不一样的碗，其实功能一模一样，不用纠结。知识库或代码就像是"饭"一样，你用什么大差不差的容器来盛，其实差别不大。

---

## 二、图谱与黑盒取舍：坚决不用 Code Graph / Code Base

关于 code graph、code base 这两个东西，在我现在有的代码基础上，坚决不要用它。那个东西其实不用 AI 的能力，那是个黑盒，就是为了省 token 的代码，小的仓库下没有必要用那个。这个是确定性，我已经得出的结论。

---

## 三、Graphify 路线反思与人工蓝图的优势

Graphify 是 CC 已经放弃的路线，AI 开发的时候不会更新这个知识图谱，开发着开发着一堆前后矛盾的内容打架。

并且这个东西的话，如果以代码为图谱，让 AI 去读一个从代码生成的一个图谱，还不如让 AI 读代码呢，代码是事实呀。你这个图谱来自于代码，可能会忘了更新就会出错啊。而真正的好的地图应该是人工维护的，是代码中无法体现的，那就是我的蓝图应该比这个更好。

---

## 四、Understand Anything 与蓝图的关系

Understand anything 是一个让我能学习任何项目的一个很好的控制，以后就用这个来学习。

另外，如果这个东西自己能看的话，那把自己能理解的给 AI，这才是一个好的知识库。比那些自己看不懂的——虽然是"白盒"，但自己看不懂，那也没有什么用。

这个东西感觉和我的蓝图挺像的。
