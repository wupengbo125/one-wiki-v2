# OpenViking 记忆机制：原始 Session 与长期记忆的流转逻辑

## 核心机制

OpenViking 对 Agent 的记忆管理分为两层，二者严格隔离：

```
+-------------------------------------------------------------+
| 对话进行中 (turn_end)                                         |
| -> 自动追加到 viking://user/sessions/<session_id>/messages   |
|    (仅作为当前会话的原始流水暂存，新会话绝对无法跨会话检索)      |
+-------------------------------------------------------------+
                              |
                              | 触发 Commit (三种途径)
                              | 1. 会话结束 (session_shutdown 退出/关闭终端)
                              | 2. Token 累积达到阈值 (默认 20,000 Tokens)
                              | 3. 手动执行 /viking commit
                              v
+-------------------------------------------------------------+
| 后台 LLM 提炼与去重 (Compressor / Extraction)                 |
| -> 提炼成画像、偏好、事件，写入 viking://user/memories/       |
|    (成为真正生效的长期记忆，所有新会话均可自动语义召回)          |
+-------------------------------------------------------------+
```

### 关键认知
1. **原始流水不等于有效记忆**：每轮对话结束后自动保存的只是 Session 原始日志，新会话检索只搜 `memories/` 和 `resources/`，不读未提炼的 Session。
2. **Commit 是唯一生效门槛**：没有 commit 的信息，新会话永远查不到；一旦 commit，提炼后的结论进入 `memories/` 终身生效。

## 艾宾浩斯复习问答（SRS Q&A）

### Q1: OpenViking 中，为什么新开一个会话无法检索到上一个会话随口说出的个人偏好（如老家、宠物）？
**A1:** 
因为每轮对话自动保存的内容仅停留在当前会话的原始流水区（`sessions/`），新会话检索只对长期记忆区（`memories/`）和资源库（`resources/`）开放，不会跨会话读取未经提炼的原始会话。

### Q2: 将 OpenViking 的临时会话转化为跨会话生效的长期记忆，触发 Commit 的三种方式是什么？
**A2:**
1. **会话关闭自动触发**：退出或关闭终端会话（`session_shutdown` 事件）时自动执行 Commit（哪怕只聊了一句话）。
2. **Token 阈值触发**：单次会话中途累积 Token 达到预设阈值（默认 `commitTokenThreshold: 20000`）。
3. **手动触发**：在会话中主动输入 `/viking commit` 立即触发后台提炼。
