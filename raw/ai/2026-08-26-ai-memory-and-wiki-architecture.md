# AI 独立第二大脑（记忆系统）与人类知识库（Wiki V2）解耦设计方案

## 1. 核心设计背景与第一性原理

传统的 AI 记忆系统常陷入两个误区：
1. **死记硬背与全量上下文塞入**：把具体配置、代码、参数全部背在 Prompt 或记忆里，导致上下文爆炸且容易过时。
2. **污染人类知识库**：把琐碎的机器配置、部署端口、调试碎片直接写入知识库，导致人类真正阅读时充斥着无价值垃圾信息。

**第一性原理洞察：**
* **人类的大脑不存在百科全书**：人类记忆的核心是“事件轮廓”与“我的笔记在哪里（寻址指针）”。
* **人类知识库只属于人类**：知识库（Wiki）是人类系统性思考与深度阅读的资产，必须保持纯净高密度；AI 必须拥有自己独立的第二大脑（记忆库）。

## 2. 独立第二大脑（one-memory）与人类知识库（Wiki V2）分工拓扑

```text
+-----------------------------------------------------------------------------------+
|                           【AI 独立第二大脑：one-memory】                          |
|  - 不存大段百科全书，只存“认知轮廓 + 寻址指针”                                     |
|  - 拥有完全自主的内部底稿与本能常识（如配 Token 知道直奔 exports）                   |
+-----------------------------------------------------------------------------------+
       │                                                      │
       ▼ [路径 A：本能直达]                                   ▼ [路径 B：深度寻址]
+------------------------------------+   +------------------------------------------+
|  【内部常识 / 专用 Skill 指针】     |   |      【人类深度知识库：one-wiki-v2】       |
|  - 局域网 IP / 部署端口 / 机器拓扑  |   |  - ⚡ 热层 (wiki/)：分级地图与自包含精品   |
|  - 调用专用 Skill (如 omni-model)  |   |  - 🧊 冷层 (raw/)：原始长文与不可变底座    |
|  -> 零摩擦闭环，无需翻看文档        |   |  -> 仅在超出本能时，按指针精准调阅人类思考 |
+------------------------------------+   +------------------------------------------+
```

## 3. 人类记忆的“两念流转模型”

人类在处理问题时并非直接背诵全文，而是极快速的两念闪回：

1. **第一念（记忆系统 · 闪回感知）**：
   * 触发情境 $\rightarrow$ 脑中闪过：“我知道这事怎么解决（或我知道这篇笔记在 Wiki 哪处）”。
   * **形态**：极简条目，不存物理数值。
2. **第二念（物理底稿 · 精准调取）**：
   * 若属自身本能：直接去固定环境位置（如 `exports`）拿取最新参数。
   * 若属复杂深度知识：带着第一念的物理指针，直奔 Wiki 具体卡片翻阅。

## 4. 记忆系统的三维回忆机制

记忆库（`one-memory`）支持人类特有的三条回忆通路：

| 回忆维度 | 触发场景示例 | 寻径流程 | 最终动作 |
| :--- | :--- | :--- | :--- |
| **📅 时序回溯 (Timeline)** | “我们上周三/昨天干了什么？” | 查 `memories/timeline/YYYY-MM.md` | 输出当日事件流水脉络 |
| **🔍 场景感知 (Context)** | “我们之前做过监控大屏吗？” | 匹配领域卡片概要（如 `worldmonitor.md`） | 获知做过此事，必要时翻阅内部底稿 |
| **⚡ 动作指引 (Action)** | “如何给新 Agent 配置 AI Token？” | 匹配动作指针（Action Pointer） | 直接提示/调起专用 Skill (`one-config-...`) |

## 5. 边界与治理铁律

1. **绝对禁止污染人类 Wiki**：
   AI 运行中产生的配置片段、端口记录、调试过程只能沉淀至 `one-memory/`，绝不往 `one-wiki-v2/` 塞入碎片。
2. **Wiki 外部指针单向引用**：
   `one-memory` 可以持有指向 `one-wiki-v2` 的寻址指针，但在人类 Wiki 内部无需关心 AI 记忆结构。
3. **大模型拟人化闭环**：
   大模型加载 `one-memory` 后，具备自主解决已知问题的“本能直觉”；在遇到深度专业议题时，懂得向人类知识库“借脑寻址”，真正成为用户的“第二个我”。

## 6. 艾宾浩斯复习问答（SRS Q&A）

### Q1: 为什么 AI 的记忆库（one-memory）与人类知识库（one-wiki-v2）必须物理彻底隔离？
**A1:** 
人类知识库是供人类阅读、系统化思考与沉淀的高密度精品资产，若允许 AI 随手写入机器配置碎片与调试日志，会导致人类知识库迅速垃圾化失去可读性；AI 拥有独立的记忆库既能自给自足处理机器琐碎，又能通过纯净指针按需借阅人类知识。

### Q2: 人类记忆的“两念流转模型”在 AI 记忆架构中是如何实现的？
**A2:** 
第一念由 `one-memory` 承担，仅存储“我知道这事怎么做 / 我知道它在哪个 Wiki 路径”的极简轮廓与指针（极低 Token 消耗）；第二念在需要实操时被激活，根据指针定点去读取环境配置或 Wiki 底稿，实现零冗余、低开销的精准执行。

## 7. 未来演进设想：高频肌肉记忆区（LRU 动态热池）

### 核心痛点与定位
日常高频本能操作（如 Git 规范提交、常用脚手架命令、高频开发口令）属于无需思考的“肌肉记忆”。人类在做这些操作时甚至不会触发“第一念寻址”，而是直接条件反射。若将这些高频碎词放到深层记忆树中去分级检索，既冗余又迟钝。

### 架构设想（Future Work）
1. **高频专属热区（Top-of-Mind / Working Memory）**：
   开辟一个极小、极轻量的独立区域，专门维护当前周期的最高频提示词与操作模板。
2. **动态自适应生命周期（LRU 频次淘汰机制）**：
   * **自动上浮**：被频繁调用的操作/指令自动注册并保活在热区，实现零检索成本即时调用；
   * **自然淡出**：长期不用的内容随时间权重衰减，自动从热区中移除并归档，保证热区始终精简。
3. **系统定位**：
   作为 AI 第二大脑的“L1 缓存”，专供高频肌肉记忆，与 L2（领域/时序记忆树）及 L3（人类深度 Wiki）构成完整的全阶记忆体系。
